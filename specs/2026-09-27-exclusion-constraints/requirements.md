# Phase 7: Schema, exclusion constraints — Requirements

Roadmap: Stage B, phase 7 (est. 8 min). One atomic commit.

## Goal

Make the database itself refuse a double-booking: a room holding two sessions at once, a tutor in two places at once, or a student in two places at once. This must hold even when two receptionists click at the same moment, so it is enforced with PostgreSQL `EXCLUDE` constraints, not only with checks in code (`DECISIONS.md` §3, "Where each rule is enforced").

## In scope

- The `btree_gist` extension, declared in the EF model (`HasPostgresExtension`) so the migration creates it.
- `sessions.slot`: a stored generated column `tstzrange(starts_at, ends_at, '[)')`.
- `attendees.slot`: a `tstzrange` column filled by a `BEFORE INSERT` trigger that copies the slot from the attendee's session.
- Three `EXCLUDE USING gist` constraints (below).
- One migration, `ExclusionConstraints`: the extension part is generated by EF, and the rest is raw SQL in `Up`, reversed in `Down`.

## Out of scope (later phases)

- Turning a constraint error (`23P01 exclusion_violation`) into a 409 → phase 11.
- Rules checked in code (6 a day, Monday, opening hours, 2 attendees) → phase 11.
- Setting `legacy_violation` on seeded rows → phase 8.
- Automated tests for the constraints → phase 12 (API-level, on a throwaway DB).

## Decisions (confirmed with the owner of this repo)

| Topic | Decision | Why |
|---|---|---|
| `sessions.slot` | Generated column, created in raw SQL, **not mapped** in EF. | It only exists for the constraints. Code reads and queries `starts_at`/`ends_at`. The EF model stays small, and the pending-model-changes test stays valid. |
| `attendees.slot` | Filled by a `BEFORE INSERT` trigger from `sessions.slot`, **not mapped** in EF. | Code cannot forget to set it or set it wrong, so the seed loader and the create endpoint need no extra step. A session's time never changes after creation (no `PUT`, see DECISIONS §3), so no `UPDATE` trigger is needed. |
| Range type | `tstzrange`, half-open `[)`. | The columns are `timestamptz`. Half-open means a 09:00–10:00 lesson and a 10:00–11:00 lesson in the same room do **not** overlap. |
| Validation | Manual psql checks inside `BEGIN … ROLLBACK`. | The throwaway test DB and API tests come in phase 12, and those tests also exercise these constraints. |

## Constraints

| Name | Table | Definition |
|---|---|---|
| `ex_sessions_room_slot` | `sessions` | `EXCLUDE USING gist (room_id WITH =, slot WITH &&) WHERE (cancelled_at IS NULL AND NOT legacy_violation)` |
| `ex_sessions_tutor_slot` | `sessions` | `EXCLUDE USING gist (tutor_id WITH =, slot WITH &&) WHERE (cancelled_at IS NULL AND NOT legacy_violation)` |
| `ex_attendees_student_slot` | `attendees` | `EXCLUDE USING gist (student_id WITH =, slot WITH &&) WHERE (status <> 'cancelled' AND NOT legacy_violation)` |

- The names are stable: phase 11 maps each one to a conflict kind (`room-overlap`, `tutor-overlap`, `student-overlap`).
- **`no_show` still blocks.** Only `cancelled` frees a student's slot (DECISIONS §1 assumptions).
- **`legacy_violation`** leaves out only the **later** row of each overlapping seeded pair. The earlier row stays covered, so a new booking on that slot is still refused.
- **Exam pair:** two attendees in one session are two different students, so the student constraint does not fire. The room constraint sees one session.

## Invariant the code must keep

The student constraint looks only at the attendee's own `status`. So **when a session is cancelled, all its attendees must be cancelled too**, or a cancelled session would still block its students. Phase 13 (cancel) and phase 18 (move) must keep this. The reverse, "the last attendee cancelled cancels the session", is already in DECISIONS §3.

## Trigger

```sql
CREATE FUNCTION attendees_copy_slot() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    SELECT slot INTO NEW.slot FROM sessions WHERE id = NEW.session_id;
    RETURN NEW;
END $$;

CREATE TRIGGER trg_attendees_copy_slot
    BEFORE INSERT ON attendees
    FOR EACH ROW EXECUTE FUNCTION attendees_copy_slot();
```

`attendees.slot` is `NOT NULL`. The FK to `sessions` already guarantees the session exists, so the copy always finds a value.
